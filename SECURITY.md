# Security policy

## Supported versions

We release security updates for the latest minor line in the current major version (e.g. `0.1.x` while `0.x` is current). When `1.x` is published, prior major lines may not receive patches unless explicitly stated in the changelog.

## Reporting a vulnerability

**Please do not open a public GitHub issue for security reports.**

Instead, report vulnerabilities privately using one of these options:

1. **GitHub Security Advisories** (preferred if enabled on this repository): use _Security → Report a vulnerability_.
2. **Email**: contact the maintainers at the address published on the repository or organization profile (if any).

Include:

- A short description of the issue and its impact
- Steps to reproduce or a proof-of-concept, if possible
- Affected versions or commit ranges, if known

We aim to acknowledge receipt within **5 business days** and to coordinate disclosure once a fix is available.

## Disclosure process

1. Maintainer confirms the report and assesses severity.
2. A fix is developed (often on a private branch or security advisory draft).
3. A patched version is published and documented in `CHANGELOG.md`.
4. Public disclosure after users have a chance to upgrade (typically aligned with the release).

Thank you for helping keep users of **react-offline-first** safe.
